```typescript
export function validateAddress(address: string): { valid: boolean; error?: string }
```

- Trim and lowercase the input
- Return `{ valid: false, error: "..." }` if address contains "outside" or ZIP code "99999"
- Return `{ valid: false, error: "Please provide a complete address including street, city, and ZIP code." }` if address is less than 10 characters

State-based response mapping:
- **IDLE**: Return greeting text "Hi, I'm Aiva. How can I help you today?" — stay in IDLE (this is the initial greeting, state moves to CLASSIFYING when user interacts via quick actions or types "schedule", "job", "estimate", "book")
- **CLASSIFYING**: Return text "I can help you with that. What type of scheduling would you like?" + ScheduleTypeMessage widget with the 3 schedule type options → transition to AWAITING_SCHEDULE_TYPE
- **AWAITING_SCHEDULE_TYPE**: This state is handled by widget interaction, not text input. If text arrives, respond "Please select a schedule type above."
- **AWAITING_ADDRESS**: Return text "Great choice! What's the service address?" → stay in AWAITING_ADDRESS (this is the prompt). When user provides address, call `validateAddress()`:
  - If invalid: return error text message, stay in AWAITING_ADDRESS
  - If valid: return "Perfect, I found availability for that area." + BookingSummaryMessage widget with mockClient data, mockTimeSlots, user's scheduleType → transition to AWAITING_SLOT_SELECTION
- **VALIDATING_SERVICE**: Immediately transition to AWAITING_SLOT_SELECTION (transparent validation step)
- **AWAITING_SLOT_SELECTION**: Handled by widget interaction. If text arrives, respond "Please select a time slot and confirm above."
- **CONFIRMING**: Generate job ID as `JOB-${Math.floor(Math.random() * 90000) + 10000}`, return success text "Job #JOB-XXXXX created for [formatted date/time]. The appointment has been confirmed." → transition to BOOKED
- **BOOKED**: Return text "Is there anything else I can help you with?" → stay in BOOKED
- **ERROR**: Return text with the errorMessage from bookingData, or generic "Something went wrong. Please try again."

For IDLE state keyword detection: if userInput (lowercased) contains "schedule", "job", "book", "estimate", or "appointment", transition to CLASSIFYING.

Each response creates a full ChatMessage object with `id: crypto.randomUUID()`, proper role, type, timestamp. Widget messages include the widget data in their `data` field.
